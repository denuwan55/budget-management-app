## Architecture

**MindfulSpend** is a fully client-side PWA (no backend). All data lives in IndexedDB via Dexie.js. The app is deployed to GitHub Pages at `/budget-management-app`.

### Layered architecture

```
React UI → Hooks → Engine (pure functions) → Repositories → Dexie → IndexedDB
```

- **`src/db/`** — Dexie schema (`database.ts`), data interfaces (`models.ts`), per-table repository classes (`repositories/`), and predefined categories (`categories.ts`).
- **`src/engine/`** — Pure functions with no DB access (except `monthRollover.ts`). `budgetCalculator.ts` is the core math; `verdictEngine.ts` maps numeric results to 5 severity levels; `recurrenceEngine.ts` generates obligation instances for recurring patterns.
- **`src/hooks/`** — `useBudgetData()` is the primary reactive hook (uses Dexie `useLiveQuery`); `useTrendsData()` aggregates 6-month history for charts.
- **`src/components/`** — Screen-level folders (`quickcheck`, `dashboard`, `obligations`, `purchases`, `trends`, `settings`) plus `layout/` (AppShell + BottomNav) and `shared/` (Modal, ConfirmDialog, CurrencyInput, etc.). `TrendsScreen` is lazy-loaded.

### Data model

Three main tables in Dexie v2 schema:
- `months` `(++id, &yearMonth)` — monthly budget with total available and savings target
- `obligations` `(++id, monthId, status, dueDate)` — bills, supports recurring with status tracking
- `purchases` `(++id, monthId, matchedObligationId, category, createdAt)` — spending entries
- `settings` `(&key)` — key-value config

### Key data flows

**Impact Check** (Quick Check screen): user enters amount → `checkImpact()` computes free pool, daily budget impact %, savings/obligation risk → `verdictEngine` maps to severity → rendered with animation.

**Month Rollover**: system detects missing current-month record → `MonthRolloverModal` prompts for new total/savings → `performRollover()` creates month and generates recurring obligations.

### Testing

Tests live in `src/test/` and cover engine functions and integration scenarios. The `happy-dom` environment is used (configured in `vite.config.ts`). Tests do not test React components — they target pure engine functions and repository logic.

### Build notes

- `npm run build` automatically runs `scripts/generate-icons.mjs` (requires `sharp`) before Vite builds.
- The `TrendsScreen` is code-split and lazy-loaded (`~372 KB` chunk).
- PWA service worker is generated by `vite-plugin-pwa` (Workbox).
- `basename="/budget-management-app"` is set in `App.tsx` for GitHub Pages routing; `public/404.html` handles SPA redirect.
